# 开发流程入口

toLink-Rag 是纯后端项目，本技能不再使用 L1/L2/L3 车道，也不按文件数判断复杂度。它只选择下一站：

```text
代码改动请求 ─────────────→ backend-delivery
整个模块目标或商业前提未成形 → module-planning
运行故障且尚未授权修复 ─────→ incident-triage
解释、审查、研究或状态报告 ─→ 直接完成只读任务
```

已有匹配的 `.specs/<KEY>/solution.md` 时直接恢复 `backend-delivery`；用户已经明确调用下游 skill 或当前正在实施时，不重复路由。

读取用户请求、`AGENTS.md`，以及区分“交付、规划、排障、只读”所需的最小代码证据。不要在入口阶段扫描完整模块、估算工作量、展开风险矩阵或创建文档。

用户明确给出的选择必须原样传递：

```text
工作流：自动 | 开启 | 关闭
路径：自动 | 直接实现 | 方案先行
后续：自动 | 直接施工 | 契约验收
```

等价自然语言同样有效。`工作流：关闭` 只跳过项目流程分流和 Spec，不跳过真实代码核实、必要验证、安全底线或 Git 授权边界。

默认输出请求类型、一个足以完成路由的事实、下一站和用户控制项。证据不足时只做一次最小只读调查。
