# 模块规划

```text
读取来源 → 核实事实 → 建立决策树 → 逐项确认 → 展示完整草稿
→ 用户确认 → 按用户指定位置写入并读回 → 停止或进入 flow-router
```

本技能不创建本地 Spec、不实现代码、不修改 Issue。用户要求写入飞书时，必须先读取相应飞书 skill，确认完整草稿后再写入并立即读回；没有写入要求时只在对话中交付规划结果。

读取 `AGENTS.md`、当前请求、明确关联材料、相关代码、测试和 `docs/`。把信息分成已核实事实、仍需调查的事实和用户必须决定的选择。事实继续调查，不包装成用户问题。

按依赖顺序建立决策树，每次只把最上游的一项交给 `decision-grilling`：`confirmed` 写入草稿，`blocked` 暂停，`replan` 撤销受影响结论并重排。

完整草稿应让接手者理解为什么做、当前怎样、本次做到哪里、主要方案如何运行、哪些边界已经确认、看到什么结果算完成。只写已确认结论，不保留聊天记录、被淘汰方案堆栈、机器阶段、方法级清单或尚未确认的建议。

写入外部文档前必须再次展示完整草稿并获得明确确认。写入成功后立即读回；读回失败只能报告“写入状态未知”，保留 token 或链接并停止，不能重复创建。

用户只要求规划或没有继续开发授权时停止。已授权继续时进入 `flow-router`，原样传递用户选择的路径，不重复索要相同授权。
