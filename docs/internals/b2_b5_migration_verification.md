# B2–B5 迁移验收矩阵

本矩阵以 Java 当前接口、Web 调用和四份 `solution.md` 为基线。单元测试与本地 `curl` 只证明其实际执行的场景；真实写入、消息消费、索引及 Java/Python 等价性必须在隔离环境分别验证。测试数据一律使用临时账号、唯一名称和可追踪对象 key，结束后核对数据库、存储与 MQ 残留。

## 执行分层

| 层 | 运行方式 | 覆盖边界 |
| --- | --- | --- |
| 单元 | `PYTHONPATH=. pytest -q tests/unit` | 业务规则、错误优先级、缓存/消息/存储替身与失败守卫；不证明真实服务可用。 |
| 本地 HTTP + Dev 只读 | 用 Dev 配置启动 `scripts.acceptance.b1_local_api:app`，运行 `scripts/acceptance/b2_b5_live_probe.py` | 真实 Java token、Python 鉴权、Dev MySQL 读、参数校验、写入关闭门禁；专用启动器不消费 Dev MQ。 |
| 单模块受控写入 | 只开启一个模块写开关，使用有固定清理范围的临时账号/对象和 `scripts/acceptance/b4_isolated_write_probe.py` 或 `scripts/acceptance/b2_object_storage_probe.py` | 真实 HTTP→数据库/MinIO 的局部行为；执行后必须核对并清理测试数据，不能替代端到端验收。 |
| 隔离写入联调 | 对专用 MySQL schema 升级 0039→0041，装配独立 Redis/MQ/MinIO 和测试用户，再打开对应模块开关 | 创建/更新/删除、缓存失效、MQ 投递、对象存储、解析与索引；不得以共享 Dev 上关闭写入的探针代替。 |
| 双端合同 | 同一隔离数据向 Java 与 Python 发相同请求，逐字段比较 HTTP 状态、业务码、数据和持久化副作用 | 证明迁移前后行为等价；差异需在切流前明确修正或批准。 |

## 当前环境前置条件

共享 Dev 的 `alembic_version` 仍为 0039；0040 候选表和 0041 outbox 表尚未执行。Java Dev 实际运行密钥已在本机 Git 忽略的配置中对齐，跨端旧密文读取不再阻塞。B2 通用上传的匿名权限与网关路径切流、本地文件模式需求尚未定案，B5 配套图片包尚未迁移。任何一个缺口未关闭时，不能宣称 B2–B5 完整验收通过或打开对应写入开关。

## 2026-09-28 本地执行结果

`b2_b5_live_probe.py` 共 61 个真实 curl 场景：61 个通过、0 个断言失败、0 个未验证。两项 B3 存量模型配置读取由受控 503 恢复为 200，并检查响应有脱敏字段且不含 `apiKey`。`b4_isolated_write_probe.py` 在仅开启 B4 写开关的本地进程中通过创建、重复名、读取、更新、配置完整替换、无效阈值与不可变向量绑定检查；临时数据集、配置、用户及登录事件均已按精确 ID 清理。

`b2_object_storage_probe.py` 初次发现默认 Dev 配置的公开桶名不匹配，四类 PUBLIC 上传报 500；临时覆盖桶名后直接 MinIO 匿名 GET 为 403。现已将 Dev 桶名改为 `tolink-dev-public`、公开 URL 改为同源预览路径，并由 Python 在单独开关下读取 PUBLIC 桶。再次以真实 curl 复测：六类上传和 SDK 读回、四类 PUBLIC URL 200 与 Content-Type、RAW/PRIVATE 经公开路径 404、四种失败输入均通过；6 个测试对象已精确删除。实际网关切流和通用上传权限矩阵仍待确认，不据此宣称 B2 完整切流。
